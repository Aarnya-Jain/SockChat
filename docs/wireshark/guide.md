# Wireshark Demonstration & Packet Analysis Guide

## Computer Networks Lab (24B15CS313) PBL

This guide details how to capture, filter, and analyze the raw TCP network traffic generated by the **Collaborative Canvas** application.

---

## 1. Network Setup & Prerequisites

- **Network Interface:** Loopback (`lo` or `127.0.0.1`) when running locally, or `eth0` / `wlan0` when testing between machines on a LAN.
- **Port Numbers:**
  - `9999` : Raw TCP Socket Core (`server/socket_server.py`)
  - `8080` : Web Bridge & HTTP/SSE Server (`server/app.py`)

---

## 2. Launching Wireshark Capture

1. Open **Wireshark**:
   ```bash
   sudo wireshark
   ```
   *(Or run CLI capture using `tshark -i lo -f "tcp port 9999"`)*

2. Select the **Loopback: lo** interface (since client bridge and socket server exchange packets locally).
3. In the display filter bar at the top, enter:
   ```wireshark
   tcp.port == 9999
   ```
   Click the blue arrow or press **Enter**.

## 3. Step-by-Step Viva Demonstration

### Step 1: TCP Three-Way Handshake
1. In your browser or terminal client, initiate a connection (join or create room).
2. Observe the first 3 packets in Wireshark:
   - **Packet 1 (SYN):** `Client -> Server [SYN] Seq=0 Win=65495 Len=0`
     - The client initiates connection to port 9999, advertising Initial Sequence Number (ISN).
   - **Packet 2 (SYN, ACK):** `Server -> Client [SYN, ACK] Seq=0 Ack=1 Win=65483 Len=0`
     - The server acknowledges client's SYN (`Ack = Seq + 1`) and announces its own ISN.
   - **Packet 3 (ACK):** `Client -> Server [ACK] Seq=1 Ack=1 Win=65495 Len=0`
     - Three-way handshake completes. Connection enters `ESTABLISHED` state.

### Step 2: Room Creation / Join Payload
1. Look for the next `PSH, ACK` packet from client to server:
   - Expand the **Data** or **Payload** view in Wireshark.
   - You will see the application protocol string:
     ```json
     {"type":"create_room","name":"Alice"}
     ```
     followed by the byte `0x0a` (`\n` newline framing delimiter).
2. Observe the server's immediate TCP `ACK`, followed by a `PSH, ACK` containing:
   ```json
   {"type":"room_created","room":"A7K92","user":{...}}
   ```
   and the full `room_state` payload.

### Step 3: Chat Transmission & Sequence Number Tracking
1. Send the text `"Hello Networks Lab"` in the room chat.
2. Filter or follow stream:
   - Right-click packet -> **Follow** -> **TCP Stream**.
   - Note the relative Sequence (`Seq`) and Acknowledgement (`Ack`) numbers incrementing strictly by the number of payload bytes transmitted.

### Step 4: Canvas Drawing Stream & Vector Optimization
1. Drag the mouse on the canvas to draw a stroke.
2. In Wireshark, note a series of compact segments:
   ```json
   {"type":"draw","x1":142.5,"y1":180.2,"x2":148.0,"y2":185.6,"color":"#ef4444","width":4,"mode":"pen"}
   ```
3. **Viva Discussion Point:** Explain to the examiner that transmitting compact vector deltas (under 100 bytes) rather than full raster bitmaps (megabytes) conserves orders of magnitude of network bandwidth and prevents bufferbloat.

### Step 5: Connection Teardown (Four-Way Handshake)
1. Click **Leave Room** or close the browser tab.
2. Observe the graceful TCP teardown:
   - `Client -> Server [FIN, ACK]`
   - `Server -> Client [ACK]`
   - `Server -> Client [FIN, ACK]`
   - `Client -> Server [ACK]`
3. Connection transitions from `FIN_WAIT_1` -> `CLOSE_WAIT` -> `LAST_ACK` -> `TIME_WAIT` -> `CLOSED`.

## 4. Wireshark Display Filter Cheat Sheet

| Purpose | Wireshark Filter |
| :--- | :--- |
| All Socket Core Traffic | `tcp.port == 9999` |
| Handshake SYN Packets | `tcp.port == 9999 && tcp.flags.syn == 1` |
| Teardown FIN Packets | `tcp.port == 9999 && tcp.flags.fin == 1` |
| Application Data Payloads | `tcp.port == 9999 && tcp.len > 0` |
| Web Bridge HTTP Traffic | `tcp.port == 8080` |
| Filter by Specific Room Code | `frame contains "A7K92"` |
